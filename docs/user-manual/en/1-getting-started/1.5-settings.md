# 1.5 Personalization

This section describes how to configure CC Switch according to your preferences.

## Open Settings

- Click the **gear** button in the top-left corner
- Or use the shortcut `Cmd/Ctrl + ,`

## Window Behavior

### Launch on Startup

When enabled, CC Switch automatically runs when the system starts.

- **Windows**: Implemented via the registry
- **macOS**: Implemented via LaunchAgent
- **Linux**: Implemented via XDG autostart

### Close Behavior

| "Minimize to tray on close" | When you click the window's close button |
|--------|-------------|
| On (default) | The window hides to the system tray and the app keeps running in the background |
| Off | The app exits completely |

Keeping it on is recommended, so you can switch providers quickly from the tray.

### Lightweight Mode

Starting from v3.13.0, CC Switch adds **Lightweight Mode** — a **tray-only** running state that minimizes desktop footprint when idle.

**How to enter**: Right-click the tray icon → click **Lightweight Mode**. The main window is **destroyed** (not just hidden), freeing UI resources and memory.

**How to exit**: Click **Open main window** from the tray menu, or trigger CC Switch via deep link / relaunch. The window is **rebuilt on demand**, with state preserved.

| Aspect | Minimize to Tray | Lightweight Mode |
|--------|------------------|------------------|
| UI process | Kept in memory | Fully destroyed |
| Idle resource footprint | Same as normal run | Near zero |
| Reopen speed | Instant (direct show) | Slightly slower (window rebuild) |
| Tray switching | Available | Available |
| Deep link wake | Available | Available (on-demand rebuild) |

> 💡 **Use case**: If CC Switch runs in the background for long periods and you mainly switch providers via the tray menu, enabling Lightweight Mode significantly reduces memory usage.

> ⚠️ **Note**: Lightweight Mode state is not persistent — the next normal launch returns to normal mode. Combine with Launch on Startup for long-term use.

### Apply to Claude Code Extension

When enabled, the provider of the Claude Code extension in VS Code follows CC Switch when you switch (writes `primaryApiKey` to `~/.claude/config.json`).

> 💡 **Use case**: If you use both Claude Code CLI and the VS Code extension, enable this option to keep both configurations in sync.

### Skip Claude Code First-Run Confirmation

When enabled, skips the first-run confirmation that Claude Code shows on its first launch, suitable for users already familiar with Claude Code.

> ⚠️ **Note**: This option writes `hasCompletedOnboarding: true` to `~/.claude.json`; turning it off removes the field.

### Homepage Display

Choose which applications to display in the app switcher on the main page. Each app can be toggled independently, but at least one must remain visible.

Configurable apps: Claude Code, Codex, Gemini, Grok Build, OpenCode, OpenClaw, Hermes, Pi, MiniMax Code.

The same group also has a **Show project switcher** toggle that controls whether the project switcher appears at the top of the main page.

> 💡 **Use case**: If you only use Claude Code and Codex CLI, you can hide the other apps to keep the interface clean.

### Skill Storage Location

Choose the directory where CC Switch stores the master copies of your Skills:

| Option | Description |
|--------|-------------|
| CC Switch (default) | Stored in `~/.cc-switch/skills/`, managed centrally by CC Switch and synced to each app |
| `~/.agents/skills` | Stored in `~/.agents/skills/`, following the Agent Skills open standard so compatible tools can read it directly |

### Skill Sync Method

Set the sync method when installing skills to each app's directory:

| Method | Description |
|--------|-------------|
| Symlink | Creates symbolic links pointing to skill source files; saves space, syncs in real-time |
| Copy Files | Copies skill files entirely to the target directory |

> 💡 **Recommended**: Symlink is the default method. Switch to Copy Files if you encounter permission issues.

### Codex App Enhancements

Contains two toggles, both off by default:

**Keep official login when switching**:

- **Off**: Every switch to a third-party provider deletes `~/.codex/auth.json`, so Codex has no official login while you use the third-party provider. Before deleting it, CC Switch stashes the login on this computer (`~/.cc-switch/codex-login-stash.json`, not included in cloud sync) and restores it automatically when you switch back to the official provider, so you don't need to log in again
- **On**: Switching to a third-party provider keeps `~/.codex/auth.json`, so the official login stays in place while you use the third-party provider and features that need it keep working

A third-party provider's API key is always written only to `~/.codex/config.toml` and never to `auth.json`. See the guide [Keep Codex Remote Control and Official Plugins While Using Third-Party APIs](../../../guides/codex-official-auth-preservation-guide-en.md).

**Unified Codex session history**: When enabled, the official subscription runs under a shared custom provider ID, so official and third-party sessions appear in the same history list; you can optionally migrate existing official sessions as well (they are backed up automatically before migration). When turned off, they can be restored from the backup. Note: when you continue an old session with a different provider, that provider's backend may be unable to decrypt the reasoning content in the session, and the continuation will fail. See the guide [Unified Codex Session History](../../../guides/codex-unified-session-history-guide-en.md).

## Directory Configuration

Settings → Advanced → Configuration Directory

### App Configuration Directory

The storage location for CC Switch's own data, defaulting to `~/.cc-switch/`.

### CLI Tool Directories

You can customize each CLI tool's configuration directory:

| Setting | Default | Description |
|---------|---------|-------------|
| Claude Directory | `~/.claude/` | Claude Code configuration directory |
| Codex Directory | `~/.codex/` | Codex configuration directory |
| Gemini Directory | `~/.gemini/` | Gemini CLI configuration directory |
| Grok Build Directory | `~/.grok/` | Grok Build configuration directory |
| OpenCode Directory | `~/.config/opencode/` | OpenCode configuration directory |
| OpenClaw Directory | `~/.openclaw/` | OpenClaw configuration directory |
| Hermes Directory | `~/.hermes/` | Hermes configuration directory |
| Pi Directory | `~/.pi/agent/` | Pi agent configuration directory |

MiniMax Code does not support overriding the directory here. MiniMax Code's data directory defaults to `~/.minimax/` and can be set with the `MINIMAX_DATA_DIR` (or `MAVIS_DATA_DIR`) environment variable; Hermes also recognizes `HERMES_HOME`, and Pi also recognizes `PI_CODING_AGENT_DIR`.

> 💡 **WSL**: CC Switch does not detect WSL automatically. On Windows, you can set a directory to a path inside WSL (e.g. `\\wsl.localhost\Ubuntu\home\<username>\.claude`); CC Switch then reads and writes the configuration inside WSL, and the "About" page also detects and updates that tool in the corresponding WSL distribution.

> ⚠️ **Note**: After changing directories, the app must be restarted, and the corresponding CLI tools must also be configured to use the same directory.

## Data Management

### Export Configuration

Click the "Export SQL Backup" button to save a SQL backup file containing:

- All provider configurations
- MCP server configurations
- Prompt presets
- Usage logs
- App settings

The exported file name format is `cc-switch-export-{timestamp}.sql`.

### Import Configuration

1. Click "Select SQL File"
2. Select a previously exported backup file
3. When the button changes to "Import", click it to start importing
4. After a successful import, the backup ID that was created automatically before the import is shown

> ⚠️ **Note**: Importing will overwrite existing configuration. It is recommended to export your current configuration as a backup first.

## Advanced Settings

Settings → Advanced Tab

### Configuration Directory

Customize configuration file directories for each app. See the "Directory Configuration" section above for details.

### Data Management

Import/export configuration backups. See the "Data Management" section above for details.

### Backup & Restore

The Backup Management panel provides full control over database backups.

#### Auto-Backup Settings

| Setting | Options | Default |
|---------|---------|---------|
| Auto-backup Interval | Disabled, 6h, 12h, 24h, 48h, 7d | 24 hours |
| Backup Retention | 3, 5, 10, 15, 20, 30, 50 | 10 backups |

When an interval is set, CC Switch automatically backs up the database on schedule. Older backups beyond the retention count are automatically removed.

#### Backup List

The panel displays all existing backups with:
- **Display name** (auto-generated from timestamp, e.g., `db_backup_20260315_143000`)
- **Creation time**
- **File size** (e.g., "1.5 MB")

#### Backup Operations

| Action | Description |
|--------|-------------|
| **Backup Now** | Create a backup immediately |
| **Restore** | Restore the database from a selected backup. A safety backup of the current database is created automatically before restoring |
| **Rename** | Change the backup's display name |
| **Delete** | Permanently remove a backup (with confirmation) |

> ⚠️ **Important**: Restoring a backup overwrites the current database. A safety backup is always created before the restore operation, so you can recover if needed.

### Cloud Sync

Sync configurations across multiple devices via **WebDAV** or **S3-compatible storage**; only one of the two can be enabled at a time. Uses **v2 protocol** with dual-layer versioning for improved reliability.

#### WebDAV

| Setting | Description |
|---------|-------------|
| Provider | Jianguoyun / Nextcloud / Synology NAS / Custom |
| WebDAV Server URL | WebDAV server URL |
| WebDAV Account | Login username |
| WebDAV Password | Login password (app-specific password; saved credentials are preserved if left unchanged) |
| Remote Root Directory | Remote storage path (default: `cc-switch-sync`) |
| Sync Profile Name | Device profile name (default: `default`) |
| Auto Sync | When enabled, every database change is uploaded automatically |

#### S3-Compatible Storage

| Setting | Description |
|---------|-------------|
| Provider | AWS S3 / MinIO / Cloudflare R2 / Alibaba Cloud OSS / Tencent Cloud COS / Huawei OBS / S3 Compatible (Custom) |
| Region | e.g. `us-east-1`; use `auto` for R2 |
| Bucket | The bucket that stores the sync data |
| Access Key ID / Secret Access Key | Access credentials |
| Endpoint | Can be left empty for AWS; required by most S3-compatible services |
| Remote Root Directory | Default: `cc-switch-sync` |
| Sync Profile Name | Default: `default` |
| Auto Sync | When enabled, every database change is uploaded automatically |

#### Operations

| Action | Description |
|--------|-------------|
| **Test Connection** | Verify that the service address and credentials are valid |
| **Upload** | Upload local database to remote. Shows progress spinner |
| **Download** | Download remote database. Shows remote snapshot info (protocol version, DB version, timestamp, size) before confirming. A safety backup of the local database is created automatically before overwriting |

#### Auto-Sync

When **Auto Sync** is enabled:
- A confirmation dialog is shown on first activation
- After every database change, CC Switch automatically uploads the database to the cloud
- The panel shows the last sync time; if an auto sync fails, the error is displayed and the upload is retried on subsequent changes

#### Remote Snapshot Info

Before downloading, CC Switch displays details about the remote snapshot:
- Protocol version (v2)
- Database compatibility version
- Timestamp of the remote backup
- File size
- Compatibility status (warning if incompatible)

> ⚠️ **Note**: Upload overwrites remote data, and download overwrites local data. A safety backup is always created before downloading.

### Application Diagnostic Logs

| Setting | Description |
|---------|-------------|
| Enable Diagnostic Logs | Controls `cc-switch.log`; does not affect request usage records or `crash.log` |
| Log Level | error / warn / info / debug / trace |

Log level descriptions:

- **error** - Critical errors only
- **warn** - Warnings and errors
- **info** - General information (default)
- **debug** - Detailed debugging information
- **trace** - All verbose information

## ChatGPT Accounts

Sidebar → **Accounts**

Sign in to ChatGPT accounts here, then pick one under "Sign-in method" on a Codex **OpenAI Official** card. Switching to that card writes the account's login into Codex's `auth.json`; cards set to "Follow Codex login" keep using the Codex CLI's own login.

**What you can do here**:

- Add ChatGPT accounts through the Device Code flow: CC Switch shows a verification code, and you confirm it on the OpenAI page that opens
- View the signed-in accounts, their sign-in status, and their subscription quota
- Sign in again when an account's login has expired
- Remove individual accounts or sign out of all accounts at once

Account credentials are stored in `~/.cc-switch/codex_oauth_auth.json`. Sign-in and quota requests use CC Switch's global outbound proxy configuration.

## About Page

Settings → About Tab

### Version Information

Displays the current CC Switch version number, with support for:

- Viewing release notes
- Checking for updates
- Downloading and installing new versions

### Local Environment Check

Automatically detects installed CLI tool versions:

| Tool | Detection Contents |
|------|-------------------|
| Claude Code | Current version, latest version |
| Codex | Current version, latest version |
| Gemini CLI | Current version, latest version |
| Grok Build | Current version, latest version |
| OpenCode | Current version, latest version |
| OpenClaw | Current version, latest version |
| Hermes | Current version, latest version |
| Pi | Current version, latest version |

Click the "Refresh" button to re-detect. When an update is available, you can update a single tool or use "Update All". Missing tools show an install button. Installs and updates run silently in the background—the button shows progress and versions refresh automatically when done. Tools that are installed but cannot run in the current environment (for example, because the Node.js version is too old) are marked "Installed · can't run".

On Windows, if you set a tool's directory to a WSL path in "Configuration Directory", the "About" page detects and updates that tool in the corresponding WSL distribution.

### Manual Install Commands

This section is collapsed by default; click the heading to expand it. It lets you copy the install commands for all tools in one click: Claude Code, OpenCode, and Hermes use their official install scripts (Claude Code and OpenCode fall back to npm if the script fails), and the other tools are installed with npm. On Windows, Hermes uses a PowerShell install script and the other tools use npm. For each tool's install command, you can also refer to [1.2 Installation Guide](./1.2-installation.md#optional-install-the-tools-to-manage).
