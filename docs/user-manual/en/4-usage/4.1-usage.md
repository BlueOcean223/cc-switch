# 4.1 Usage Statistics

## Overview

The usage statistics feature records and analyzes API request data, helping you:

- Understand API usage patterns
- Estimate cost expenditure
- Analyze usage patterns
- Troubleshoot issues

Usage data comes from each tool's local session logs: by default, CC Switch periodically scans the session logs of Claude Code, Codex, Gemini CLI, Grok Build, OpenCode, Pi, and MiniMax Code and tallies requests, tokens, cache hit rate and cost by provider and model.

- **Codex sessions**: **Precisely parsed** from JSONL session logs; model names are normalized for consistent pricing lookup
- The usage panel supports **per-app filtering** so data from different apps does not mix
- OpenClaw and Hermes don't support usage statistics yet
- Request records written by the local routing of older versions are kept and still count toward the statistics

## Prerequisites

1. ✅ The corresponding CLI has session history files
2. ✅ "Scan session logs automatically" stays on (on by default). When it's off, scanning only happens on manual sync

## Statistics Overview

### Summary Cards

Key metrics displayed at the top of the page:

| Metric | Description |
|--------|-------------|
| Total Requests | Total number of requests in the time period |
| Tokens Processed | Cache-normalized total of input + output + cache creation + cache read tokens |
| Cache Hit Rate | Cache read tokens as a share of cacheable input |
| Estimated Cost | Cost calculated based on pricing configuration |
| Success Rate | Percentage of successful requests |

Starting from v3.15.0, the top of the Usage page uses a filter-driven Hero card. When you change the date range, app, provider, or model filters, the Hero's Tokens Processed, cache hit rate, request count, and cost update together and stay aligned with the logs and stats below.

> Note: v3.15.0 normalizes cache reads, cache creation, and OpenAI-style cache reporting. Historical token and cost numbers may differ from older estimates; the current numbers follow the normalized rules.

## Trend Charts

### Request Trend

Line chart showing the trend of request counts:

- X-axis: Time
- Y-axis: Request count
- Viewable by hour/day
- Supports zoom and drag

### Token Trend

Shows token usage trends:

- Input Tokens (blue) - Prompt content sent by the user
- Output Tokens (green) - Response content generated by AI
- Cache Creation Tokens (orange) - Tokens consumed when first creating cache
- Cache Hit Tokens (purple) - Tokens saved by reusing cache
- Cost (red dashed line, right Y-axis) - Estimated cost

> 💡 **Cache Token explanation**: Anthropic API supports Prompt Caching. Creating cache incurs a higher fee (typically 1.25x input price), but subsequent cache hits only charge 0.1x, significantly reducing costs for repeated requests.

## Pricing Configuration

### Open Pricing Configuration

Sidebar → **Usage** → the "Pricing" tab at the bottom of the page

Besides entering prices manually, you can click "Import from models.dev" in the "Add Pricing" / "Edit Pricing" dialog to import public model pricing.

### Configure Model Prices

Set prices for each model (per million tokens):

| Field | Description |
|-------|-------------|
| Model ID | Model identifier (e.g., claude-3-sonnet) |
| Display Name | Custom display name |
| Input Price | Price per million input tokens |
| Output Price | Price per million output tokens |
| Cache Read Price | Price per million cache hit tokens |
| Cache Creation Price | Price per million cache creation tokens |

### Model ID Normalization Rules

Before matching pricing, CC Switch normalizes the requested model ID:

- Remove everything before the last `/` and convert to lowercase
- Remove everything after `:` and trim a trailing `[1m]`
- Replace `@` with `-`
- Remove common wrapper prefixes, version suffixes, and date suffixes (`-YYYY-MM-DD`, `-YYYYMMDD`)
- Some model families can match a short ID to a versioned pricing entry

When adding pricing entries, enter the normalized Model ID rather than the full raw model name from the request.

| Raw model name | Model ID to enter | Note |
|-------|-------------------|------|
| `stepfun-ai/step-3.5-flash` | `step-3.5-flash` | Removes the provider prefix |
| `moonshotai/kimi-k2-0905:exa` | `kimi-k2-0905` | Removes the prefix and the `:` suffix |
| `gpt-5.2-codex@low` | `gpt-5.2-codex-low` | Replaces `@` with `-` |
| `OpenAI/GPT-5.5-2026-05-14` | `gpt-5.5` | Removes the prefix and date suffix |
| `anthropic/claude-opus-4.8` | `claude-opus-4-8` | Removes the prefix and matches dotted format |
| `global.anthropic.claude-opus-4-8-v1:0` | `claude-opus-4-8` | Removes wrapper prefix, version suffix, and `:` suffix |
| `claude-haiku-4-5` | `claude-haiku-4-5-20251001` | Matches a short ID to versioned pricing |

### How Cost Is Calculated

- Cost is an estimate based on the pricing table. When you change a model's price in the pricing settings, its existing records are repriced right away. If you edit `model-pricing.json` directly, or an update changes the built-in prices or the pricing rules, records are repriced at the next launch.
- Requests are priced at the rate in effect when they were made: models whose official price changed have their earlier prices built in, and requests before the change use the earlier price. This currently covers GPT-5.6 Sol (cut on 2026-08-21), GPT-5.6 Terra and Luna (cut on 2026-07-30), and Claude Sonnet 5.5 cache reads (cut from $0.20 to $0.10 per million tokens on 2026-10-07).
- Claude 1-hour cache writes cost 2x the input price; fast / priority mode uses the model's multiplier.
- A request whose prompt (input, cache reads and cache writes together) exceeds the long-context threshold is billed at the higher rate in full:

  | Model | Threshold | Higher rate |
  |------|------|------|
  | GPT-5.4 and later (except mini and nano) | 272K | Input side ×2, output ×1.5 |
  | Claude Sonnet 4 / 4.5 (with the 1M context window) | 200K | Input side ×2, output ×1.5 |
  | Claude Haiku 5.5 | 100K | Input side and output ×5 |
  | Gemini Pro | 200K | Input side ×2, output ×1.5 |
  | xAI Grok | 200K | Input side and output ×2 |

  "Input side" means input, cache reads and cache writes. For models priced in several steps, such as Qwen and Doubao (for example 32K and 128K), the highest step the prompt exceeds applies; importing from models.dev brings in every step.
- Grok Build uses the cost recorded by the CLI (returned by xAI). Pi and OpenCode are priced from the pricing table first and fall back to the cost they recorded only for models missing from the table. MiniMax Code uses the cost it records.
- After an update to import or pricing rules, click "Rebuild Usage" under "Data sources" to re-import all usage from the session logs. Days whose logs have been deleted keep their existing daily totals.

### Custom Prices

Prices you add, edit or delete in the "Pricing" tab are saved in `~/.ccs-lite/model-pricing.json`. They take priority over the built-in prices and are kept across updates. Relay services may charge different prices; edit the model's price to match:

1. Click the "Edit" button
2. Modify prices
3. Save

To go back to a built-in model's price, remove the model from `models` in `model-pricing.json` (and from `deletedModelIds` if you deleted it in the app), then restart the app.

When upgrading from upstream CC Switch, prices of built-in models that were edited only in the database are moved into `model-pricing.json` so they are kept. The app lists those models once after launch.

## FAQ

### Statistics Data Is Empty

Check:
- Is "Scan session logs automatically" on, and does the corresponding CLI have session history
- Does the app support usage statistics (OpenClaw and Hermes don't yet)

### Cost Estimates Are Inaccurate

Possible causes:
- Pricing configuration doesn't match actual prices
- Using a relay service with special pricing

Solutions:
- Update pricing configuration
- Refer to the provider's actual invoices

### Token Count Differs from Provider

CC Switch uses its own method to estimate token counts, which may slightly differ from the provider's calculation. Refer to the provider's invoice for authoritative numbers.
